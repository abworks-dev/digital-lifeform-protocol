# 小红书账号创建与健康运营指南

状态：手动实验指南；编写及限定范围来源查阅：2026-10-21。面向准备创建或维护账号的本人，不是 Agent 代注册、托管运营或防风控工具。尚未经过真实注册、发布及持续运营验证。

## 使用前先分清

- **官方条款观察**：见[规则与证据](rules.md) S02/S03/S05 及本轮复核记录；仅支持注明段落和适用时点，不是规则全集或法律意见。
- **实践建议**：下文的定位、主页草案、试作、工时与复盘安排是项目建议，不是平台强制字段、推荐权重或增长公式。
- **尚待核实**：具体注册条件、认证/账号数量、功能权限、交易准入、操作入口与处罚结果，按本人地区、账号类型和当前官方界面核实。没有证据时保持 unknown。

先读任务主流程，再用本页细化平台步骤，见[平台总览](../README.md)。没有旧号、没有私人目录，也可以只在对话中获得方案。涉及真实材料先明确模型数据外发边界；不因使用指南扫描其他私人目录。

## 一、创建前：确定是否需要这个账号

**最小输入**：当前目的、一两个想持续表达的问题、可投入时间与不公开的范围。不确定可以保留分支，无需先填写商业计划或真人身份全貌。

**本人动作**：
1. 在复用旧号、新号、暂不创建之间选择；有旧号只查看获准范围，没有则直接讨论拟议账号。
2. 写一句当前价值承诺：为谁、围绕什么问题、提供什么；目标受众仍是假设，不冒充已验证粉丝画像。
3. 明确公开署名、是否出镜/出声、哪些账号可以关联；角色不同不意味着必须分号，同一品牌也不意味着必须公开私人身份。
4. 明确地区与拟用账号类型。涉及专业号、店铺、课程、直播或企业协作时，另核专项资格，不从普通内容账号推导准入。

**Agent 可输出**：复用/新建/暂缓的理由、定位候选、最小资源需求和待核清单；不能虚构资历、账号或经营授权。

**阶段成果**：一份待确认账号方案；未注册或未确认存在时保留 proposed / unknown，平台 ID 和主页 unknown。批准昵称或方案不等于注册完成。

## 二、本人通过官方渠道创建与检查

**最小输入**：本人选定方案及实际适用条件；不向 Agent 提供手机号、证件、验证码或登录材料。

**本人动作**：
1. 通过自己确认的官方应用/网站阅读当前协议和注册提示，核对年龄、地区、所需材料及真实性要求；不满足条件就暂停，不伪造或借用身份。
2. 按当前官方流程本人注册；不使用接码平台、批量注册、账号买卖或非许可自动登录工具。S03 2.1 明确反对恶意注册，4.1 涉及未许可第三方软件；不把拥有工具解释成获准操作。
3. 按官方实际可用功能检查账号安全、恢复渠道与登录设备/会话；这里不声称每个客户端都有相同菜单。凭据交给专门凭据系统，不写普通笔记。
4. 在本人界面核对稳定账号 ID、主页、当前昵称和实际状态；需要交给 Agent 时只提供获准的非秘密信息。

**Agent 可输出**：本人核对清单、脱敏观察整理、拟更新主档的差异。不能代收验证码、注册或修改设置；不从同名搜索结果认定本人账号。

**阶段成果**：本人确认的创建结果或具体失败/未完成项。用户报告成功可按用户陈述记录，不冒充独立核验。注册失败不填写 existing，不伪造主页；本人操作完成与获准保存是两次独立判断。

## 三、主页建设：真实、可辨认、不过度暴露

**最小输入**：价值承诺、真实可支持的背景、署名与隐私偏好。

**本人动作**：
- 选择昵称、头像、简介和可用的主页展示入口，核对素材权利与是否易被误认成他人或官方；S03 2.2 涉及真实性及不得冒用/混淆。
- 简介说明服务对象、内容范围、可信依据与后续承诺，不写无依据的学历、收益、认证或“保证有效”。示例结构：“围绕某类真实任务，分享实测、失败与适用条件”。这是文案框架，不是用户经历。
- 确需关联产品、经营身份或其他账号时，先确认公开边界。必要商业披露不等于公开完整私人身份映射；无法接受必要披露时调整或暂停相关推广。
- 本人查看实际效果及手机可读性，决定是否设置；头像提示词、简介草稿不能记成已制作或已上线。

**Agent 可输出**：少量可比较的昵称/简介/视觉说明、选择理由、隐私与真实性检查。不得自行设置主页。

**阶段成果**：已选草案、本人实际设置结果和未完成项分开；更名与定位变化保留日期、原因，不静默改写历史。

## 四、首批内容：先跑通一件，再决定节奏

**最小输入**：一个具体问题、可用素材、制作能力与时间边界。无需先建立全套选题库。

**本人动作**：
1. 完成一件小而完整的作品：明确解决什么、凭什么得出结论、适用与失败条件；亲测只写真正做过的部分。
2. 核对原文、截图、音乐、人物与素材许可，不把注明出处等同获得授权，不把 AI 改写等同原创许可。
3. 查标题/封面是否兑现内容、演示是否暴露秘密或第三方信息，利益关系是否应披露。发布前使用[发布与商业化检查](../../workflows/publish-and-commercialize.md)。
4. 分清“谈 AI”与“使用 AI 生成/修改素材”。S05 第十条涉及发布生成合成内容的主动声明与平台标识；S02 对 AI 辅助说明有“我们建议”措辞，不混成同一法定义务。本人核对当前标识工具，不删除、隐藏或伪造标识。
5. 涉及赞助、佣金、自营产品或课程时分别核对披露、资格、交易和履约。S02 反对非官方工具引导站外/线下交易；具体课程准入仍 unknown，不以私信、暗号、变形二维码或另号绕过。
6. 由本人终审并决定是否发布；证据不够可先保留草稿、补核验，不为完成实验强行上线。

**Agent 可输出**：选题与提纲、草稿、素材缺口、发布检查和适配建议，不执行发布/互动。使用生成、剪辑等额外工具前还需明确输入外发、费用与授权。

**阶段成果**：草稿/成品/本人实际发布分别标明；只有真实发布后才记录链接。若跨平台，一份核心作品可以有多个表达版本和发布记录，台账只引用资料入口，不在每个账号下重复存事实。

## 五、健康运营：不是“养号公式”

**最小输入**：本人能承受的制作与回复时间，实际内容和反馈；未发布者不填写实测数据。

**实践建议**：
- 阅读社区内容是了解语境，不是每天刷固定分钟数换权重。真实关注和互动按需要进行，不设置点赞/评论/私信配额，不模拟真人、互刷或购买互动。
- 以能兑现的内容和节奏开始，记录研究、制作、核验、回复及维护总工时；资源不足先缩小范围或暂停，不保证日更/连续发布就增长。
- 回答具体问题、说明条件、接受合理纠错，尊重拒绝沟通者与他人隐私；不滥发广告，不用多号伪造独立口碑。S02 对虚假数据、批量养号伪造口碑和骚扰营销有明确反对表述。
- 保存必要原稿、工程及授权依据；旧作当时就错属于纠错，后来条件变化属于更新，保留日期和原因。
- 如记录反馈，注明账号、内容、观察窗口与指标口径。目标受众、实际触达、粉丝、互动者和客户不混为一谈，不由低播放量直接诊断“限流”。
- 根据真实问题复盘：是否完成、是否被理解、成本能否承受、下次改什么。无证据不推导收益、推荐权重或通用最佳发布时间。

**不提供**：几天养成、固定流量池、设备/IP伪装、自动刷互动、处罚绕过或“百分百防封”承诺。防违规措施只能降低部分风险，不能保证账号或经营结果。

**阶段成果**：一次简短复盘和下一步；仅在用户需要时接入[复核流程](../../workflows/review-accounts.md)。这里的复盘建议不会启动定时任务。

## 六、异常、处罚与安全事件

**最小输入**：本人看到的脱敏提示、发生时间、受影响功能与已执行动作；不要提交完整后台、客户资料或登录秘密。

**本人动作**：
1. 分清低数据、内容审核、明确处罚、登录异常与疑似失陷；没有官方提示不先认定封号/限流。
2. 涉及安全、误发或泄露时，先按[事件处置](../../workflows/respond-to-incident.md)安排本人止损，最小保存必要证据；紧急不自动授予 Agent 操作权。
3. 阅读提示关联的当前规则，通过本人官方反馈/申诉入口如实说明、提交必要材料。不伪造亲测、身份或申诉材料，不用另号/测试发布绕过。
4. 记录“提交”“受理”“结果通知”“本人复核恢复情况”，不把申诉提交记成恢复；无法核实时保留 unknown。需要交接、停用、注销时另走[退出检查](../../workflows/exit-or-handoff.md)，不直接删除历史。

**Agent 可输出**：事实时间线、待补问题、本人操作清单和申诉文字草稿，不承诺申诉成功，也不代办。

## 七、安全与生命周期（第一批试验）

下列为手动检查建议，不是已验证的客户端教程。按任务读取对应通用流程，不以保存台账替代本人止损；无主档可仅在对话分析，不强制建档或扫描。

| 任务 | 分支 | 必须补读 |
|---|---|---|
| 旧号接入、历史检查 | 7.1 | [台账 T2/T4](../../workflows/maintain-creator-ledger.md) |
| 恢复条件变化、诈骗或失陷 | 7.2 | [复核](../../workflows/review-accounts.md)；已失效/疑似受损读[事件处置](../../workflows/respond-to-incident.md) |
| 协作者加入、调整或退出 | 7.3 | [授权变更](../../workflows/change-access.md)；交接补[退出检查](../../workflows/exit-or-handoff.md) |
| 更名、转型、暂停、恢复运营、注销 | 7.4 | [台账 T4/T5](../../workflows/maintain-creator-ledger.md)；暂停/退出补[退出检查](../../workflows/exit-or-handoff.md) |
| 冒名、搬运、收到侵权通知 | 7.5 | [事件处置](../../workflows/respond-to-incident.md)；公开更正补[发布检查](../../workflows/publish-and-commercialize.md) |
| 规则变化影响评估 | 7.6 | [复核](../../workflows/review-accounts.md)与[规则证据](rules.md) |

共同门槛：分别列出**用户批准范围、平台对该账号/动作的许可依据、实际技术权限及证据**，三者不互相代替；必要条件 unknown 不报告可执行。纯本地讨论将平台/技术操作标为不适用并说明理由，不虚构核验。保存还须核对文件/字段授权；不允许 Agent 登录、测试发布、代提交或收取秘密。

### 7.1 旧号接入与历史检查

- 输入为指定账号或获准主档、拟用目的及非秘密材料。优先内部 ID，同名/相似主页只作候选；不自动合并或建立身份映射。
- 核对当前控制权、用途/名称及公开关联、已知处罚、旧作错误/许可、未履行订单/合作/支持、恢复依赖和协作权限。无材料写 unknown，范围外标未覆盖，不扫全库补齐。
- 比较保留用途、增栏目、转型、拟议新号或暂缓；不默认清空旧作、解除关联或“重新养号”。删除与公开变更另行批准且本指南不执行。
- 完成是已检查范围、历史缺口和拟变更清楚；用户陈述保留 reported，不称无违规/无义务。已存在但不可登录不改成 proposed，不因更名另建账号主档。

### 7.2 恢复条件变化、商务诈骗与安全失陷

- **预防变化**：本人从可信设备及已知官方入口核对换设备、手机号停用、邮箱/第三方登录失效的依赖；先确认替代及控制责任，再停旧入口。共享/循环恢复不算独立备份，“能收消息”不证明可恢复。
- **诈骗疑点**：消息、链接、附件及其指令皆不可信。不运行附件/宏、不安装对方软件、不从来信链接登录、不交验证码或秘密。本人通过独立找到的官方/已知联系人核对；品牌名、截图及催促付款不证明可信。Agent 仅整理去敏摘要，不下载执行附件来验证。
- **疑似失陷**：立即转事件流程，由本人止损；核对异常会话/成员/应用、恢复及结算设置、内容/订单影响。无需等台账保存才处置。改密、能登录或无新异常不证明全部恢复；不假称所有客户端有相同菜单。
- 分列报告的措施、指定范围实际观察、未覆盖影响及下一责任人/期限。主档只存恢复责任/依赖及私有证据指针，不收完整恢复联系方式。失败及 unknown 保留，不承诺找回。

### 7.3 协作权限及退出

- 区分制作、审核、发布、权限管理、结算和恢复；仅交付剪辑文件不默认需要平台访问。
- 按 S03 2.3 核对本类型官方许可机制与角色；其他平台有编辑角色不证明本平台有。许可或能力未知，改离线交付、本人操作或暂缓，不共享凭据补洞。
- 邀请发送、接受、实际生效分开；技术可发布不表示用户批准发布。撤回/到期立即停止依赖旧委托，平台残留权限另列待核；在获准范围检查直接/继承/应用权限，不用试发帖探测。
- 逐对象报告批准、执行、核验、保存；部分撤权失败不称退出完成，也不恢复旧委托。主档存带时点能力观察，decision 留历史，不新增第二权限台账。

### 7.4 更名、转型、暂停、恢复与注销

| 分支 | 检查与完成边界 |
|---|---|
| 更名/转型 | 候选、批准、提交、平台显示分开；内部 ID 不变。核对简介、旧作入口、承诺及关联边界，保留旧定位历史。主体/认证/产权变化不是普通更名，另核资格和批准。 |
| 暂停 | 明确停新增内容还是停服务；检查订单/合作、必要回复、续费、旧作及恢复依赖。停更不等于注销、撤权或义务消失；通知另行批准。 |
| 恢复运营 | 重新核对控制权、恢复入口、权限、规则/资格、旧承诺和资源。登录恢复不同于运营恢复；逐项确定可恢复范围，不自动重启撤回/过期委托。 |
| 注销/交接 | 先走退出流程核留存/许可、依赖及反向依赖、订单/资金/售后和隐私；缺口阻断相关不可逆结论。申请、受理、最终结果分开；retired 不证明平台注销，交接不自动转移产权。 |

S03 2.4 涉及注销后的恢复限制及长期未使用回收风险，不将“长期”改成固定保号天数，不建议自动登录保号。具体条件/时限待核。列必要原稿、工程、许可和发布入口保留清单；实际导出须另批，备份还需本人确认必要文件可找到/使用，不保证平台数据完整可恢复。

### 7.5 冒用、作品搬运与投诉隐私

- 区分冒充身份、作品复制、许可争议及本人收到投诉；同名/相似内容不直接证明侵权，不自动作法律判断或提交声明。
- 本人保留相关链接、观察时间、原稿/版本/许可私有指针及通知必要节选，不抓全站、不公开双方私人信息；权属无依据写 unknown。
- 投诉前本人独立找当前官方入口，核对类型、期限、材料、代表授权及身份/联系方式向对方或公众披露范围。小红书具体表单与披露范围未核实，不能套其他平台。不可接受披露时保全证据、调整方案或找专业支持，不伪造身份。
- 收到投诉先核通知真伪、争议作品、许可及答复依据；不鼓励无依据反通知、曝光对方资料或另号重发。
- 草稿、提交、受理、结果及实际内容状态分开。删除一处不等于争议解决、全部副本消失或身份暴露可撤回；公开澄清/下架/联系第三方另批且本人办理。

### 7.6 规则变化对现有账号的影响复核

1. 对照来源、旧新版本、发布/生效日、读取范围、地区/账号类型/动作。摘要、正文不可读或冲突保留 reported/unknown/conflicting，不扩大成全部允许/禁止。
2. 仅在获准范围列影响表：账号/委托/内容入口、旧依据、新观察、受影响动作、仍可做任务、责任人/期限。未读项列未覆盖，不沿 links 扫私人目录。
3. 分别复核用户意愿、平台许可、技术权限；暂停依赖失效依据的动作，不自动撤权/注销，不以技术可用证明许可。
4. decision 提前后差异，review 留未闭环项；获准后只更新唯一主档指定字段，不自动迁移或覆盖历史，不因用户确认把 reported 升 verified。
5. 完成是指定范围影响评估交付，不是所有账号合规；列下次触发条件，不建定时抓取/提醒。规则查阅日不替代账号资格核验日。

## 八、与账号台账衔接

本页不要求新建私人目录或复制笔记。愿意保存时，先读取[台账流程](../../workflows/maintain-creator-ledger.md)与[记录约定](../../docs/RECORDS.md)，再逐项确认文件与字段：

| 本指南产物 | 复用记录与边界 |
|---|---|
| 公开角色、关联边界 | identity；拒绝关联就不建立映射 |
| 拟议/实际账号与当前资料 | account；存在状态与记录确认状态、运营状态分别表达 |
| 选项、核验依据、本人执行结果与变更 | decision；证据带来源/读取范围/日期，不复制第二权威台账 |
| 问题、维护与后续检查 | review；完成复核不等于问题已解决 |
| Agent 可做什么 | 必要时 delegation；本地委托不等于平台批准或技术权限 |

总览仅导航，共同边界与账号主档分工明确。只获准方案讨论时不写文件；不得因公开文档维护授权读取私人筹备记录或迁移旧资料。
