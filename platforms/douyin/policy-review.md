# 抖音规则变化与影响复核

状态：2026-10-22 从[原指南](guide.md#规则变化复核)拆分的手动实验建议；本次只整理职责，没有新增联网取证、账号资格核验或外部操作授权。仅中国大陆抖音普通个人号，不借用小红书或 TikTok 的规则。先读[平台入口](README.md)与[共同边界](../README.md#共同边界)；官方 URL、日期、证据状态及适用边界唯一维护于[规则与证据](rules.md)，本页只做任务影响评估。

先读[账号复核](../../workflows/review-accounts.md)。需变更协作范围转[协作权限](collaboration.md)，更名／暂停／恢复／注销转[生命周期](lifecycle.md)，内容改动转[发布前检查](guide.md#发布前检查)。没有主档也可在对话中列影响，不以初始化台账阻塞判断。

## 规则变化复核

1. 指定本次公开 URL／段落和受影响任务；复用 [来源工具](../../tools/check_source_changes.py)，首次捕获仍是候选基线，原始材料和机器报告可留仓库忽略目录。不覆盖旧批次。
2. 先查读取质量与实际范围：登录／壳页／验证码／失败如实保留，不绕过。对 `unreadable` 也人工复核，DY-S04 已出现关键词误报；不改机器报告来制造通过。DY-S09–14实际来自官方公开前端明确的只读文章响应，解码文字不伪装为Jina capture；DY-S15为本次主入口缺段补读，不倒写前轮已全文读取。
3. 比较发布主体、产品／账号／动作范围、版本与生效日期、措辞及条款；搜索摘要、HTTP 200、哈希不变不是现行证明。不能只凭年份把旧资料判为失效；尚未证实现行时先记 unknown，已确认被替代或不再适用的资料才标 stale，冲突标 conflicting。保留原来源与暂定结论，阻塞依赖该项的动作而非全部本地整理。
4. review 列出受影响的账号／decision／delegation 和未核实项，另有批准才改本地记录；高影响动作前本人重新核对。无新阅读就不滚动核验日期、不自动改写权威规则、不创建后台调度。

## 影响范围与人工下一步

出现平台通知、正文／版本变化、证据冲突、产品／账号类型变化，或即将进行协作访问、商业化、投诉披露、恢复控制权、注销等高影响动作时触发复核。下表是按现有证据定位任务的检查清单，不是另一份规则表；来源的准确措辞、日期、范围和历史只在对应证据条目维护。

| 依赖的证据或缺口 | 在获准范围核对什么／下一责任人 | 不自动推出 |
| --- | --- | --- |
| [主协议旧捕获与补读](rules.md#dy-s15-主协议入口日期与缺段补读)、[CDN候选](rules.md#dy-s07-官方-cdn-协议候选补缺) | 本人从当前官方入口核完整适用正文、版本及账号通知；将旧观察与新读取分开 | 新正文成功抹去旧缺段、主站与CDN映射已认证，或查阅日就是生效日 |
| [内容标识](rules.md#dy-s12-内容标识使用规范)、[AI公告](rules.md#dy-s13-2026-ai生成内容管理公告) | 逐件核真实生成成分、需用的自主声明及当前功能；纯构思／润色保持unknown，转本人核验 | 自动“疑似AI”已完成主动声明、所有AI／多号普禁，或加标保证增长／不限流 |
| [营销提示](rules.md#dy-s14-营销创作提示)与[共同法律](rules.md#共同法律与专项排除) | 本人分别核利益关系、广告性质／可识别性、平台营销声明、合作产品准入、交易及履约 | 将呼吁／鼓励改为硬禁；平台声明、法律“广告”和商业准入相互替代 |
| [网暴](rules.md#dy-s09-网络暴力治理规范2026版)与[热点](rules.md#dy-s10-社区热点信息和账号治理规则试行) | 核具体语境、热点来源／时间地点、身份声明及争议当事人条件；材料只在官方端由本人决定提交 | 合理监督即网暴、所有评论者都须身份证明，或普通号一律不得商业化 |
| [恢复](rules.md#dy-s08-账号找回)、[隐私](rules.md#dy-s05-隐私政策)、[侵权投诉](rules.md#dy-s06-侵权举报指引)、[注销](rules.md#dy-s04-注销须知) | 本人核对应场景、披露范围、期限起点、当前材料及实际结果；分别路由到安全／权利／生命周期 | 条件性反馈期限变通用办结保证、恢复登录重启委托、提交即受理或完成 |
| [未取得的依据](rules.md#未取得的依据与人工下一步) | 普通号角色、具体合作资格／利益边界、当前界面等，列unknown及受阻动作；有实际需求才核专项 | 搜索失败或无关结果证明功能不存在，或借用小红书／企业／电商角色补洞 |

历史超时、壳页、原站空响应、图片未读、日期／来源冲突和工具误报继续由[原审阅链](rules.md#保存与复核)保留。新旧可读性不同不等于规则刚变；人工可读不等于机器通过或版本现行。确需新增公开查阅时先核授权及适用技能，仅匿名读取公开资料，不登录、不用Cookie、不读浏览器、不上传私人材料或绕过验证；搜索摘要不能当全文。

## 交付与保存边界

仅在获准范围列出：受影响账号／委托／内容、旧依据、新观察及读取范围、仍可继续的草拟、暂停的具体动作、本人待核项、责任人和下次触发。分别核对用户批准、平台许可、实际技术权限；不自动撤权、重启委托或注销。保存非必需；另获授权后沿用 decision／review 和唯一 account 指定字段，保留部分失败，不批量改私人记录或新增台账。

复核完成只表示指定范围的影响评估已交付，不表示所有账号合规、来源已批准或平台已执行。本轮只做文档结构与离线回归，结果见[本轮检查](../../tests/README.md#11-抖音专题拆分与离线回归2026-10-22)；未执行模型业务行为、工具保存或真实平台测试。返回[平台入口](README.md)。
