# 自媒体台账：静态虚构实例

首个垂直场景聚焦“单一账号主档 + 身份关系 + 变更历史 + Agent 入口”。每个账号只有一个主档，另附一个拟议方案用于展示“未创建”的表达。这里是静态虚构实例，不是模型、Agent 或真实平台运行通过报告，不证明自动化能力或真实账号可用。

全部主体使用 fictional-user；云页岛与雾灯集均为虚构平台。主页仅用保留的 .example 域名，不指向真实账号。没有读取或包含私人台账、凭据、真实身份或恢复材料。

## 人工走查点（不是通过报告）

- 检查记录 ID 唯一、frontmatter 完整、links 闭合；引用不依赖显示名猜测。
- 对照变更前后值、批准范围、本地保存和平台结果，确认不能从批准推断平台成功。
- 当前名称必须能追到观察来源，并保留未独立核实的限制。
- 拟议账号不能生成平台 ID、主页或创建成功事实。
- 导航不维护第二份当前状态；后续变更只维护主档并保留历史。

未验证：真实平台行为、模型是否遵循入口、权限强制执行、账号运营效果。需要在用户另行选择并授权的环境走查，才能附运行证据。不得为演示连接真实账号；本案例不授权提交、推送或外部操作。
