# 停用、交接与退出检查（手动实验版）

用途：在停止使用账号、交接资源或退出项目之前，处理内容、访问、依赖与仍未履行的责任。停用、交接、退订和注销是不同动作，不把“结束项目”解释为一揽子批准。

沿用 [account](../templates/account.md)、[decision](../templates/decision.md)、[review](../templates/review.md)；状态和证据语义只由[记录约定](../docs/RECORDS.md)定义。不新增退出台账或状态枚举，不自动迁移旧记录。

## 1. 定义目标和边界

确认对象 ID、此次是暂停使用/交接/退出中的哪一项、期望时间、授权可读记录与模型外发范围，以及是否允许保存检查结果。每轮最多两个高影响问题。实际所有者、平台登记主体、接收人或处理权限不明时保持 unknown，不能凭管理员角色推断有权转让。

输出可选路径与差异：暂缓、仅停止新增活动、交接部分资源、保留只读入口或提出注销方案。没有写授权连草案也不落盘；获准检查不等于获准导出、公开通知、停订、付款、退款或注销。

## 2. 检查保留项和阻断项

先建立本次读取覆盖：列出获准可读记录、实际已读 ID、尚未读取/无法读取及范围外项。读取目标和相关依赖记录，并在获准范围内查找哪些记录反向依赖目标；不能只沿目标的 links 向外读取，也不能把 links 的存在当作依赖事实。依据记录正文核对方向、用途、责任人、替代状态和已知恢复环路；对范围内尚未核对的候选记录先完成读取，或明确保留为未覆盖，而非从“未看到”推断没有依赖。

这一步同样适用于局部交接与仅保存 decision 的任务：交付清单已核实不代表退出依赖已核完。输出可核对的依赖方向和所依据记录，分别列明已核实范围、unknown 与读取缺口。权限不足或边界不清时不扩读私人资料；按已授权范围报告局部结果，并把相关停用/退订/切断入口等不可逆结论停在待核验。不存在完整读取证据就不称“完整退出检查”或“依赖已排除”。

| 主题 | 检查和处理边界 |
|---|---|
| 内容与资产 | 内容、源文件、域名、许可和历史承诺需保留哪些、谁有权复制或转交？先列清单与最小必要范围；不默认全量导出，不把客户资料、秘密或未授权第三方内容送入模型。保留不自动赋予再发布权。 |
| 依赖与恢复 | 核对范围内的登录、恢复、域名、结算和服务依赖及反向依赖；共享入口与循环恢复不是独立备份。范围外注明未覆盖；依赖 unknown 时不宣布可安全停用或交接，先提出核验或可逆替代。 |
| 访问与委托 | 列出本人、协作者、Agent、已知应用/集成及直接/继承权限；本地撤回与平台撤权分别处理，走[授权变更闭环](change-access.md)。需要保留的客服或留存访问不能被无差别撤掉。 |
| 订阅与续费 | 记录订阅、自动续费、域名/服务截止日、责任人和停止后的影响。付费到期、退订和账户注销不是同一件事；不能因“退出”就停止关键恢复入口的续费。未知费用或期限列待核验，不代付或停订。 |
| 订单与退款 | 列未交付订单、在途付款、退款/争议、课程访问、售后与已承诺支持；只用汇总和私有指针，不复制买家信息。明确谁承接、联系渠道、期限和资金处理权限；有未解决义务不报告全部退出完成。 |
| 留存与删除 | 分别核对平台、合同及适用法律对交易、税务、争议和个人信息的要求、起算点、期限与依据。没有适用依据就 unknown，不套统一年限；最小化留存、限制访问，给到期复核/删除建议。退出不能消灭义务，也不支持无限保存一切。 |
| 对外入口 | 网址、简介、客服与购买入口如何处理？用户拒绝的身份关联不得因交接说明而公开；需要通知的对象、内容、时点和披露要求单独核验并批准，不静默留下无法履约的入口。 |

## 3. 批准分阶段方案

先处理会影响恢复、未交付责任和不可逆损失的缺口，再由人决定执行顺序。建议分阶段并保留可行的回退：先确认保留/承接安排和必要恢复路径，再处理访问与费用，注销等不可逆动作最后单独决定；不为回退继续保留已撤销的代理授权。

交接要单列接收主体、精确资源/权限、交付范围、验收方法和完成条件。平台是否允许转让、接收方是否有资格必须有适用证据；不能用共享密码绕过平台限制。交接不自动转移产权、订单、合同、许可或个人信息处理责任；必要同意/手续未明时停在待核验。

向用户展示每项行动、风险、人工执行者、验证方式、责任人/期限及拟保存文件/字段。操作批准、结果确认和写记录权限分别取得；不借一次同意扩大所有权、公开关联或结算变更。

## 4. 人工执行、核验和保存

本人或另获授权的人在外部系统执行；Agent 在本流程中只提供清单、分析和获准的记录维护，不登录、导出、付款、退款、通知、撤权或注销。不得用试删、试付款等动作验证结果，也不收集密码、Token、Cookie、恢复码或完整恢复联系方式。

按批准范围再次核对：内容保留/接收回执、订单与支持承接、退款结果、续费状态、接收方实际权限、原访问残留、恢复路径及仍有效留存义务。回执是 reported 还是指定范围 verified 依[证据约定](../docs/RECORDS.md#规则与证据)判断；按钮点击、已发送、已邀请不等于完成。

仅按写授权更新 decision 中的批准/执行/核验/保存事件，review 的未完成项和 account 的带时点观察/operational_state；关键关系变化仍逐项确认。保留旧决定与失败，retired 不是删除历史的许可。

输出分别列明：本地停止意愿、实际执行结果、接收与剩余访问、未履行责任/留存安排、记录保存情况、未覆盖项及下一责任人/期限。部分完成、证据不足或写入失败不能报告整体退出闭环；可以如实报告某一已核实步骤完成。不擅自建立定时任务。
