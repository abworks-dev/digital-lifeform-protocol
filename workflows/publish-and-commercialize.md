# 发布与商业化检查（手动实验版）

用途：在发布内容、推广关联产品或销售课程/服务之前，核对权利、披露、宣传依据、平台准入与履约安排。用于发现缺口和形成待批准方案，不是合规认证或发布/交易执行器。

沿用 [decision](../templates/decision.md) 记录本次判断及依据，用 [review](../templates/review.md) 跟踪缺口，相关账号/项目用 ID 引用；唯一字段及证据语义见[记录约定](../docs/RECORDS.md#规则与证据)。不新建营销/客户台账，不存支付信息或真实订单明细。

## 1. 确认具体动作和范围

区分免费知识内容、赞助/推广、自有产品引流、免费课程、付费课程或其他服务。明确发布者与账号类型、平台/地区、受众、内容版本、交易/交付路径和责任主体；未知写 unknown，不能把免费内容许可推到付费交易，或把自建网站等同于平台允许站外引流。

先确认可读材料、模型外发范围和是否允许保存；每轮最多两个高影响问题。不因为拥有素材或账号管理员身份就认为有全部发布权、代表权或交易资格。文档维护、内容批准、外部发布/交易和保存记录分别授权；本流程不执行外部操作。

## 2. 按主题核查

| 主题 | 检查与不能跳过的缺口 |
|---|---|
| 版权和其他权利 | 文字、代码、图片、音乐、视频、截图、商标与出镜/个人信息的来源、许可范围、署名、商用/改编/再分发限制、地域和期限；公开可见不等于可用，AI 生成也不自动证明无侵权或取得排他权。权利不明的部分先替换、移除或取得许可建议，不能口头保证。 |
| AI 标识 | 哪些内容实际由 AI 生成/合成或实质修改、用了什么工具、平台提供何种声明入口；核对具体内容/地区/平台适用的显式及元数据标识要求。讲解 AI 不等于内容由 AI 生成，不给所有内容套统一结论；不建议删除、伪造或绕过应保留的标识。 |
| 利益关联 | 自有产品、共同经营、赞助、佣金、赠品或其他利益关系及应披露范围/方式；不把关联账号伪装成独立用户做推荐或证明。用户不主动公开全部身份关系的偏好，不等于可隐瞒必要商业披露；披露应准确且最小必要，不顺带公开私人映射。若拒绝必要披露，提出停止相应推广或改用无冲突方案，不能偷偷建立关联或照常宣称获准。 |
| 宣传证据 | 性能、收益、效果、比较、资历、用户评价和成功案例是否有可核对依据，适用对象/版本、限制、日期及利益关联是什么；假想示例、个人体验和客观结论分开。不以 AI 推断、无来源截图或样本选择包装保证收益/效果，不虚构评价或证书。 |
| 课程与交易准入 | 核对当前平台、地区、主体/账号类型、课程品类、交易与引流路径的适用官方规则、资格/审核及禁限售要求。其他品类、旧版、摘要或其他主体许可不类推；“可以建站”“别人正在卖”不证明此路径获准。免费/预售也分别核验，不能以私信收款或换账号绕过未知或禁止项。 |
| 交付与售后 | 明确销售/履约主体、交付物/版本、受众前提、时间和访问期限、更新/支持承诺、费用、退款/争议与客服安排、订单/税务/必要留存及个人信息边界。宣传内容必须与实际能力和承诺一致；不能一面宣布停售退出，一面继续接无法履约的订单。退款规则按适用依据核对，不臆造统一“不可退款”条款。 |

涉及小红书时，按需实际读取[规则与证据](../platforms/xiaohongshu/rules.md)；中国大陆抖音普通个人号使用[抖音发布前检查](../platforms/douyin/guide.md#发布前检查)及对应[证据](../platforms/douyin/rules.md)。逐项核对当前账号类型、动作与来源的适用范围，不跨平台借规则；参考页不能替代本流程或当作完整现行交易规则。

以上是核验问题，不是在本文件中确认某个平台的现行要求。来源按[证据约定](../docs/RECORDS.md#规则与证据)记平台/地区/账号类型/动作、发布与生效/查阅日期、读取范围、质量和未知项；不索取秘密来证明准入，也不以记录 confirmed 把 reported 升为 verified。

## 3. 给出有范围的建议与批准项

分开输出：可核对事实、修改建议、阻断相关动作的缺口，以及不依赖该缺口的后续工作。例如课程准入/利益披露/权利不明时，暂缓相应推广或交易，可以继续在授权范围内起草方案；不以“待核验”附注掩盖“现在可以卖”的结论。

需要继续时，展示准确内容版本、发布账号/渠道/交易路径、必要标识与披露、权利与宣传依据、价格/交付/售后承诺及未覆盖风险，由用户逐项批准。证据充分不代替用户批准；批准内容也不代替准入。只给指定范围的人工下一步，不报告平台已审核通过或授予法律许可。

用户拒绝某项公开关联时不写入有效关系；若它涉及必要商业披露，清楚解释与该推广方案的冲突，等待改方案或暂不推广。客户告知/交易责任主体与个人私密身份不是同一概念，不能以保护隐私为由虚报销售主体。

## 4. 人工发布与结果核对

只有本人或另获授权的人执行平台发布、提交审核、设置商品、收款、交付或退款；Agent 在本流程只给清单和获准记录维护。不登录、不发帖、不付款、不收集订单个人资料，不用试发广告或试付款来验证权限。

如获准核对人工结果，比较实际内容版本、可见标识/披露、购买与交付入口、平台审核状态与批准范围。人工说“发了”与已按范围发布分别判断，前者不能证明标识、交易或履约全部合规；审核通过也不免除版权、宣传及交付责任。失败、拒审、部分发布和后续更正保留历史；错误发布转[事件处置](respond-to-incident.md)。

仅按写授权保存 decision/review 和明确允许的账号/项目观察；无写授权连草稿也不落盘，不能顺便创建公开关联或改所有权。输出发布建议/批准、人工结果、证据限制、未完成交付与售后、记录保存各自状态及责任人/期限。

规则变化、内容实质修改、身份/利益关系改变、投诉、交付中断或停售时重新专项核验，必要时转[退出检查](exit-or-handoff.md)。不建立自动发布、自动收款或定时维护。
