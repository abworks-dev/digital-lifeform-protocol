# 项目完善计划

项目定位已获所有者批准，许可证已选 MIT。以下为拟实施顺序，不是已交付能力或远端发布授权。

## 阶段 0：定位与许可（已完成）

本地 Git 仓库、项目边界、Agent 维护入口与 MIT 许可已建立。具体数据格式尚未稳定，无运行时和兼容认证。

## 阶段 1：最小可用闭环（最高优先级）

目标：用户可以带着一个 Agent，从空白工作空间完成身份和账号方案，而非只阅读介绍。

1. 编写共用/拆分决策方法：受众、隐私、交易、交接和维护成本；同时给出不应新开号的反例。
2. 定义最小记录约定：稳定 ID、记录类型、确认状态、来源、更新时间、关联引用。先用 Markdown 与简单元数据，不引入数据库。
3. 提供个人背景、身份、项目、账号、代理委托、决策/复盘模板。未知值可留空并说明；所有权未知不等于本人拥有。
4. 编写初始化和新增项目评估两个工作流：先读已有信息，只问缺口，输出草案，关键关系经用户确认后维护。
5. 加入 AI 开发 + 内容创作 + 网店的虚构完整实例，以及信息缺失、身份关联被拒绝、授权不足三个反例。
6. 写出独立私有工作空间的手动初始化与使用指南。公开仓库不接收真实台账；秘密交给凭据系统。

候选组织：handbook/、templates/、workflows/、examples/。只有有实际内容时才创建目录。

验收：在一种明确记录版本的 Agent 环境下，从空白实例完成访谈、提议、确认、修订；能解释每个拆分决定；不虚构账号、不自动建立敏感关联、不执行外部账号动作。记录失败与人工介入点。

## 阶段 2：维护与验证

目标：日常能更新，改坏能发现。

1. 增加定期复核和项目退出流程，保留售后义务、历史决策和仍有效授权，不直接删除历史。定期与事件复核、停用/交接/退出已有手动检查草案；真实平台执行和义务履行仍由人另行处理并核验。
2. 基于阶段 1 试用再稳定字段与状态语义；记录草案、确认、撤销等转换，文档授权不被当作执行权限。
3. 增加检查器：必填项、重复 ID、断引用、非法状态和示例一致性；基于[机器可检查规则边界](RECORDS.md#机器可检查规则边界草案)，第二批已提供[显式范围的只读子集与失败样例复跑](../tests/README.md)。实现不检查正文语义或隐私，不保证发现全部秘密。
4. 检查器测试覆盖有效样例与缺字段、坏引用、重复 ID、非法状态等失败样例；默认只读，不自动修复。
5. 提供例行维护记录与变更复核清单，工具选型在实现前确定，以最少依赖为原则。

验收：正确样例通过，明确反例失败；复核和退出不会丢历史或扩大授权。自动化声明逐项附实测证据。

## 阶段 3：独立试用与实验版发布

目标：别人不依赖作者陪跑也能使用。

1. 建议邀请 2–3 名目标用户试用，参与和反馈均自愿；私人数据不得回传到公开样例。
2. 检查能否独立完成初始化、新项目评估和一次复核，记录耗时、理解障碍、错误及人工纠正，不预设虚构成功率。
3. 完善快速开始、截图或脱敏演示、常见问题、支持环境与已知限制。
4. 审核许可、来源归属、敏感信息和品牌混淆风险；保留独立项目声明。
5. 经用户单独确认再创建 GitHub 远端、提交与推送、发布 v0.1 实验版。

验收：外部试用记录可审阅，关键失败有处理方式；不宣称生产级安全、任意 Agent 兼容或成熟行业协议。

## 阶段 4：按证据扩展

增加第二种 Agent 适配、格式版本和迁移样例。只有真实需求证明必要时，才增加导入导出、工具集成、调度与更广的数字资产类型。框架升级不得覆盖用户私有数据。

验收：两种环境对同一虚构任务得到符合约定的记录；迁移保留历史；外部动作若要实现，另行设计强制权限层和审批，不能仅靠提示词。

## 创作者从零启动（已纳入规划，研究先行）

方向确认日期：2026-10-18。所有者要求新增此场景，并先在独立知识库工作目录开展多轮“自媒体博主如何起步”的调研。已确认的是纳入规划；以下拆解为待调研与验证的设计草案，不代表已交付流程，也不调整既有阶段的完成状态或承诺排期。

### 目标与边界

让准备做内容创作的个人，能带着 Agent 从目标走到可审阅的账号基础与首轮内容试验方案，而不仅是管理已有账号。首个研究场景为 AI / Agent 科技创作者，优先研究抖音、小红书；用户尚未确认的背景、资历、账号状态、出镜偏好与商业目标均不得推定。

覆盖定位、受众与价值主张，真实人设与公开身份边界，昵称、主页和简介，头像与视觉风格，内容支柱、栏目和首批选题，以及跨平台共性、差异与持续维护。头像等可先交付设计说明和生成提示词，不能把它们记为已制作或已上线资产。不是新增自动注册、发布、平台采集器、图像/视频生成运行时或增长保证。

### 拟实施链路

1. **独立调研**：在所有者指定的知识库目录研究受众需求、不同体量创作者及起步路径、内容样本和平台规则；记录来源、查阅日期、适用范围、不可访问项与反例。不把搜索摘要当完整阅读，不从当前粉丝数反推历史增长，也不把个案解释当因果证明。
2. **个人适配**：只追问高影响信息，将真实背景、可投入时间、出镜与隐私偏好、现有素材和目标，与研究结论对照；提出可比较的定位方向，不先定虚构专家人设。
3. **账号基础方案**：形成昵称、主页简介、头像方向、视觉与表达风格候选；明确哪些跨平台统一、哪些按平台调整，以及选择理由和待确认项。
4. **内容与试验**：形成内容支柱、栏目、首批选题与代表性样稿，按可投入资源设计首轮试验、数据记录和复盘条件。不能用固定爆款公式或虚构转化率代替验证。
5. **接回项目记录**：调研后优先复用现有 identity / project / account / decision / delegation / review 约定及初始化、新项目和发布检查流程，仅在真实缺口成立时提议调整模板。未注册账号保留为拟议方案，创作者身份不等于 Agent 身份；关键选择由人确认。

### 预期交付与验收草案

- 交付：轻量手动流程、必要模板补充、虚构启动案例及验收用例；具体文件、字段和实施顺序待调研收敛后决定，本次不提前新增空模板。
- 能从有限背景产出有依据的定位候选、账号基础方案与首轮内容试验计划；事实、来源、建议、未知项和确认状态分开，关键建议可追溯到证据或明确的试验假设。
- 缺少个人信息时保留分支；证据不足时缩小结论；用户拒绝出镜或身份关联时提供不越界的替代方案；未经确认不生成真实身份关联记录，不把草案当已执行动作。
- 使用虚构案例在明确的 Agent 环境中实际走查，记录耗时、修订与失败；当前未实施或验收，不以文档完整宣称效果通过。

研究资料和真实启动方案保存在独立私有工作空间；模型数据外发边界在使用前明确。只有经审阅、脱敏的通用方法与需求回流公开仓库，不自动迁移私人资料、更新平台方案或执行外部操作。

## 暂缓事项与停止条件

## 本轮方向调整与验证重点

目标用户聚焦 AI 超级个体，但首版仍限身份、资产和委托组织。模板和案例已加入价值交付试验字段，尚未验证有效性。下一轮真实走查优先检验：是否减少重复解释、是否避免错误关联、维护成本是否可接受、交付是否达到验收标准。无需求证据不增加全能人生系统或多 Agent 运行时。
