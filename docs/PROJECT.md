# 项目定位与方向

状态：项目定位与方向已获所有者审阅通过；具体字段与实现仍待设计验证。首次整理：2026-10-15。

## 定位

Digital Lifeform Protocol 是面向 AI 增强型独立开发者、创作者与个体经营者的数字身份、资产与 Agent 委托的实验性开放规范及工作空间模板。核心不是创建“另一个我”，而是表达“我有哪些角色、拥有或管理哪些数字资产、正在经营哪些项目、允许哪个代理在什么条件下做什么”。

## AI 超级个体与项目边界

本项目采用工作性定义：个人以专业判断与责任为核心，通过 AI、工具和外部协作，持续完成过去需要多人配合的价值交付。不是法定身份、收入门槛或能力认证。

组织链路为：个人目标 → 项目 → 身份 → 数字资产 → Agent 委托 → 交付与验收。账号只是入口，成果才是目的。可把工作交给专业人士，或明确暂不做；不要求一个人包办一切。

## 核心问题

1. 身份、账号与项目之间的归属和复用关系不清。
2. Agent 缺乏持久、可审阅的用户上下文，每次重新猜测。
3. 记录信息的权限容易被误认为操作外部系统的权限。
4. 项目变化后，账号、授权和公开入口没有退出流程。

## 原则

- 人类主导，授权显式，默认最小权限。
- 文件优先、可读、可版本化；先解决场景，再稳定格式。
- 私有实例与公开框架隔离，凭据交给专门凭据系统。
- 区分事实、推断和提议；所有关键关系均可确认和追溯。
- 能借用现有工具就不造新运行时，跨 Agent 兼容以实测为准。
- 不宣称本地文件天然保密，也不把提示词当作强制访问控制。

## 概念边界（候选，不是稳定 schema）

- Person：决策主体，不与数字代理等同。
- Identity：职业、创作、经营等角色及其公开关联边界。
- Account / Asset：平台入口、内容、域名等；记录实际归属、管理者和用途，不存凭据。
- Project：有目标、状态和生命周期的活动。
- Agent：可被委托的执行者及其运行环境。
- Delegation：主体、资源、允许动作、条件、有效期和撤销方式；文档记录本身不执行授权。
- Decision / Review：变更理由、证据、确认状态与复核记录。

## 首版范围

只覆盖身份、账号、项目的映射，以及 Agent 对这些记录的访谈、建议、确认和维护流程。以 AI 开发 + 内容创作 + 网店的虚构完整案例验证。

## 非目标

不训练人格分身；不承诺意识或数字永生；不做密码管理器、统一登录、区块链 DID、平台小号批量注册、反风控工具；不自动登录发帖付款；不重建通用知识库或整个人生操作系统。

## 产品组成

1. 方法层：共用/拆分、公开关联、权限与生命周期决策。
2. 模板层：身份、项目、账号、代理委托与复盘记录。
3. 流程层：初始化、新项目评估、复核、项目退出。
4. 验证层：字段、引用、状态、敏感信息与授权边界检查。
5. 适配层（后续）：对具体 Agent 的轻量入口，不建立重复规范。

## 成功证据

陌生用户能够在 Agent 帮助下产出自己的可审阅方案，解释每个共用与拆分决定；未知项不被编造成事实；没有确认就不写入关键身份关系或触发外部操作。首轮以虚构数据和人工审阅验证，不以文档数量或 Agent 数量衡量。后续试用记录重复解释次数、人工修订与越权/错误关联事件、维护耗时及交付是否被接受；不预设改善比例或把虚构案例当实测。
