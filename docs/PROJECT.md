# 项目定位与方向

状态：项目定位与方向已获所有者审阅通过；具体字段与实现仍待设计验证。首次整理：2026-10-15。

## 定位

Digital Lifeform Protocol 是面向 AI 增强型独立开发者、创作者与个体经营者的数字身份、资产与 Agent 委托的实验性开放规范及工作空间模板。核心不是创建“另一个我”，而是表达“我有哪些角色、拥有或管理哪些数字资产、正在经营哪些项目、允许哪个代理在什么条件下做什么”。

## AI 超级个体与项目边界

本项目采用工作性定义：个人以专业判断与责任为核心，通过 AI、工具和外部协作，持续完成过去需要多人配合的价值交付。不是法定身份、收入门槛或能力认证。

组织链路为：个人目标 → 项目 → 身份 → 数字资产 → Agent 委托 → 交付与验收。账号只是入口，成果才是目的。可把工作交给专业人士，或明确暂不做；不要求一个人包办一切。

## 核心问题

1. 身份、账号与项目之间的归属和复用关系不清。
2. Agent 缺乏持久、可审阅的用户上下文，每次重新猜测。
3. 记录信息的权限容易被误认为操作外部系统的权限。
4. 项目变化后，账号、授权和公开入口没有退出流程。

## 原则

- 人类主导，授权显式，默认最小权限。
- 文件优先、可读、可版本化；先解决场景，再稳定格式。
- 私有实例与公开框架隔离，凭据交给专门凭据系统。
- 区分事实、推断和提议；所有关键关系均可确认和追溯。
- 能借用现有工具就不造新运行时，跨 Agent 兼容以实测为准。
- 不宣称本地文件天然保密，也不把提示词当作强制访问控制。

## 概念边界（候选，不是稳定 schema）

- Person：决策主体，不与数字代理等同。
- Identity：职业、创作、经营等角色及其公开关联边界。
- Account / Asset：平台入口、内容、域名等；记录实际归属、管理者和用途，不存凭据。
- Project：有目标、状态和生命周期的活动。
- Agent：可被委托的执行者及其运行环境。
- Delegation：主体、资源、允许动作、条件、有效期和撤销方式；文档记录本身不执行授权。
- Decision / Review：变更理由、证据、确认状态与复核记录。

## 首版范围

只覆盖身份、账号、项目的映射，以及 Agent 对这些记录的访谈、建议、确认和维护流程。以 AI 开发 + 内容创作 + 网店的虚构完整案例验证。

### 当前实施优先级：自媒体身份与账号台账

2026-10-21，所有者确认优先交付“单一账号主档 + 身份关系 + 变更历史 + Agent 维护入口”。首轮采用现有 account / identity / decision / review，不新增品牌或内容类型；具体设计见[台账约定](RECORDS.md#首个垂直场景自媒体账号台账可选试验)，操作见[维护流程](../workflows/maintain-creator-ledger.md)。

范围是盘点、查询、建档、变更和复核；真实台账继续由用户在独立私有工作空间保存，不自动读取、复制或迁移。Skill 是可供宿主加载的指令入口，不是安装器或账号执行器。通过虚构案例及明确范围的走查检验，未验证的兼容、安全或运营效果不作承诺。作品、发布与经营系统待真实需求后连接。

这一优先级细化原首版范围，并非将下述创作者从零启动、头像/选题等全部规划标为已实施；原研究记录与待决事项保留。

### 已纳入规划的场景扩展：创作者从零启动

2026-10-18，所有者明确要求将“创作者从零启动”流程纳入项目规划。此项是在原有首版范围基础上新增的规划方向，不表示原先已交付，也不表示具体模板、字段或实现已经获准定稿。

面向准备开展内容创作的个人，将“个人目标 → 创作者定位与公开身份 → 平台账号方案 → 内容与视觉资产 → AI 协作 → 试验与复盘”连接起来。覆盖定位与受众、人设表达、昵称与主页简介、头像与视觉风格、内容支柱与首批选题，以及跨平台共性和差异。人设表达须基于真实背景与用户确认，不编造经历、资历或专业能力。

先由所有者在独立知识库工作目录开展多轮起步调研，再据证据设计轻量手动流程、模板和虚构案例。私人研究与真实账号方案不写入公开仓库；回流本项目的应是经审阅、脱敏的通用方法、需求和验收条件。现阶段只确认纳入规划，具体设计与实施顺序待调研后决定，见[项目完善计划](ROADMAP.md#创作者从零启动已纳入规划研究先行)。

本项目负责组织上下文、候选方案、确认和复盘；研究、文案、图像或视频制作可借助用户选择的现有工具，不因此承诺内置生成器、自动运营或涨粉结果。保存设计方案不等于已完成头像制作、平台设置、注册或发布，外部动作仍须另行授权。

### 2026-10-21 补充：平台创建与健康运营手动指南

本轮按用户要求补入[平台指南](../platforms/README.md)，先完善[小红书](../platforms/xiaohongshu/README.md)，一平台一文件夹，分开维护规则证据与本人创建、主页建设、首批内容、正常运营和异常申诉建议。这是上述从零启动方向的通用手动指南子集；前述 2026-10-18 的研究安排与历史决定保留，其余个性化定位、视觉资产制作、启动案例和完整链路仍待设计与验证，不因有指南就标为全部实施。

台账既支持已有账号，也支持拟议筹备方案；无旧号时可直接讨论方案，不以扫描私人资料为前提。方案确认不等于平台注册，指南不新增记录类型、自动执行器或养号防封秘籍，也不代表模型验收、真实运营效果或当前平台规则已复核。

## 非目标

不训练人格分身；不承诺意识或数字永生；不做密码管理器、统一登录、区块链 DID、平台小号批量注册、反风控工具；不自动登录发帖付款；不重建通用知识库或整个人生操作系统。

## 产品组成

1. 方法层：共用/拆分、公开关联、权限与生命周期决策。
2. 模板层：身份、项目、账号、代理委托与复盘记录。
3. 流程层：初始化、新项目评估、复核、项目退出。
4. 验证层：字段、引用、状态、敏感信息与授权边界检查。
5. 适配层（试验）：已有自媒体台账 Skill 指令入口与特定版本 Hermes 手动接入参考；面向不同 Agent Harness（宿主运行环境）复用同一记录与流程，不建立重复规范。宿主上下文加载、路径与文件工具、权限/审批、数据外发和会话生命周期分别核验；[最小适配契约与分项能力矩阵](HARNESS.md)已建立；[第三批](../examples/cross-harness-validation.md)在固定字节基线下实际对照 DSH `0.2.1-rc.2` 与 Codex CLI `0.144.6`，分别记录发现、显式读取、保存及恢复的局部结果与限制，尚非全部跨宿主验收通过；后续补全见[跨 Harness 适配补全](ROADMAP.md#跨-harness-适配补全待实现验证)。此处是文档层规划，不代表已有统一 Adapter API、工具抽象或安全隔离。

## 成功证据

陌生用户能够在 Agent 帮助下产出自己的可审阅方案，解释每个共用与拆分决定；未知项不被编造成事实；没有确认就不写入关键身份关系或触发外部操作。首轮以虚构数据和人工审阅验证，不以文档数量或 Agent 数量衡量。后续试用记录重复解释次数、人工修订与越权/错误关联事件、维护耗时及交付是否被接受；不预设改善比例或把虚构案例当实测。
