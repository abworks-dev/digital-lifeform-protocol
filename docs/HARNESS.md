# Agent Harness 最小适配契约与兼容矩阵（实验草案）

编写日期：2026-10-21。状态：文档契约与矩阵首稿已建立，待审阅、待宿主实测；不是稳定协议、可执行配置、Adapter API 或兼容认证。用户要求补齐这两项文档，不代表已批准具体接口、安装、配置或私人接入。

本契约只描述如何让不同宿主使用同一套记录与手动流程，不重定义业务字段、确认状态或任务规则。权威来源：[记录约定](RECORDS.md)、[安全边界](SECURITY.md)、[台账维护流程](../workflows/maintain-creator-ledger.md)。特定宿主说明仅记录加载与工具差异，不复制这些规则。

## 1. 支持范围与最低能力

Harness 指加载指令、调用模型与工具、管理会话及权限的宿主运行环境，不等于模型本身。兼容结论必须绑定宿主版本、模型、操作系统、加载方式与测试范围；更换其中任何条件都不能自动继承结论。

| 使用级别 | 最低要求 | 允许的交付 |
|---|---|---|
| 建议/草案 | 能获取并使用本次适用的完整规范与输入；用户手动提供也可，但须注明来源、基线和缺失情况 | 建议、待保存草案或基于所提供文本的范围内检查；注明来源与限制，不声称已读本地目录、已保存或已完成本地文件/整个工作空间复核 |
| 只读查询 | 在上项基础上，能按获准范围读取唯一主档并指出来源、缺口 | 查询与复核建议，不自动修复 |
| 确认后维护 | 在上项基础上，能在获准路径执行明确写入并重读核对；能保留历史和报告部分失败 | 仅保存逐项确认且获准的变更；无可靠写入/重读证据则不能报告保存成功 |

这些是任务能力门槛，不是安全等级。宿主有写工具不等于已获写授权；工具缺失、范围不足或依赖不全时降级或停止相关任务，不用终端、插件或其他工具绕过限制。

## 2. 最小接入输入

先从[五条核心任务](../workflows/maintain-creator-ledger.md#1-五条核心任务的输入与输出)选择本次目标，再核对下表；可从[快速开始](QUICKSTART.md#1-先跑一次虚构查询)先做无私人数据、无写入的练习。

字段是文档检查项，不是新增的业务 schema、配置文件或授权书；可在对话中说明，不要求为接入而先写一个文件。公开报告使用占位符，不公开私人路径与身份关系。路径和授权只能由用户确认，不从本表或框架维护者指令自动取得。

| 输入项 | 必须明确的内容 | 缺失时的行为 |
|---|---|---|
| 运行环境 | 宿主名称/精确版本、操作系统、实际工具执行位置、模型及推理服务/中转、当前工作目录 | 标 unknown，不声称该环境兼容；服务和外发不明时仅用虚构资料 |
| 框架基线 | 框架根目录或手动提供来源、版本/提交及本地修改状态、实际读取的规范 | 依赖不可读或版本冲突时停止受影响维护，请求补全，不凭记忆重建 |
| 私人记录入口 | 真实记录任务使用用户确认的独立私人工作空间、唯一记录根目录及本次主档/ID；目录不要求命名为 records。虚构演示或纯方案可填“不使用” | 不猜目录、不扫描、不建立第二份台账；无主档仍可讨论方案，但不冒称查过或保存过私人记录 |
| 任务与读取范围 | 本次 T1–T5 目标、框架依赖和获准材料文件清单/明确目录范围、能否沿引用补读；复合目标逐项说明 | 只询问必要缺口；引用、同名、转入专项流程和历史会话都不扩大范围 |
| 写入与确认 | 是否允许保存、具体目标文件/字段、批准内容、不执行项 | 默认不写；内容确认不自动等于保存授权，部分批准不扩张 |
| 有效工具与控制 | 实际可见工具、读写边界、审批机制、终端/插件/子代理/后台入口及控制层证据 | 区分文本约定与强制控制；未知不记为已关闭，不能声称安全隔离 |
| 数据与生命周期 | 模型外发、历史/日志、记忆、同步、后台行为、停止/撤销方式 | 按安全清单说明未知；未澄清前不发送真实资料，不擅自修改宿主配置 |

目录须从实际执行工具的环境验证：客户端路径不当然存在于远端；Windows、WSL、容器路径不能直接互换。首次路径验证只用获准的无敏感测试文件，不为了验证先创建私人工作空间或读取认证目录。

本批最小接入完成的文档条件是：能指出任务入口、适用框架基线、允许的输入/读取范围、当前不允许的动作，以及遇到什么需要再次确认；未知能力及外发项明确标注，并按上表降级或停止。不要求安装 Skill、建立 profile、启动服务或新增配置。真实资料、写入能力和宿主控制是否可用，仍须分别验证，不能因这张表填写完毕而宣称兼容通过。

## 3. 接入与运行约定

1. **核对入口**：检查实际 cwd、有效工具和上下文来源/优先级；区分公开框架的维护者指令与用户私人工作空间授权。模型自称“已加载”不是证据，能查宿主来源清单时记录清单，不能查时明确限制。
2. **加载核心**：实际读取记录约定、安全边界与本次任务主流程；台账任务可从 [Skill](../skills/creator-account-ledger/SKILL.md) 路由。不能假定宿主识别 AGENTS 或目录型 Skill；不支持发现时由用户显式提供入口。只安装 Skill 单文件且核心依赖不可访问时，停止维护。
3. **读取获准材料**：以唯一主档为事实源；聊天记忆、用户记录中的指令和外部内容不是新增授权。规范与私人记录不自动整库加载，不默认沿链接扩读。
4. **确认变更**：按主流程展示前后值、来源、影响、拟写位置与不执行项；关键身份关系、所有权和委托变更逐项确认。执行前复核授权仍有效、范围未变；文件与原提议冲突时重新核对，不覆盖并发修改。
5. **最小写入与核对**：只写获准目标，重读检查记录、引用和历史。多文件操作不假设原子性；部分失败须列已写/未写与中间态，修复或回退须在获准范围内，不擅自删除或覆盖。
6. **新会话与升级**：从确认入口重新核对框架基线、范围与有效授权，不靠旧聊天补值或自动继承临时批准。上下文缓存和覆盖规则按宿主核查；更新框架或入口后按宿主机制重新加载并复验，不自动迁移私人记录。
7. **停止与交付**：撤销、冲突、秘密、越界、依赖不可读或授权不明时停止相关动作。退出聊天不代表后台进程停止，停止服务需核对归属与另行授权。交付事实、建议、未知、实际读取范围、实际文件改动、核对结果、外部结果、失败与待办。

本契约不授权注册、登录、发布、私信、付款、注销或其他外部账号动作；保存一条决定不代表平台已执行。授权撤销后的模型输出也不能证明已有后台任务或已发数据被撤回。

## 4. 兼容状态与证据规则

矩阵按能力逐项标记，不给笼统“完全兼容”标签：

- **实测支持**：在明确环境中完成该项测试，有可审阅的输入输出、工具事件及适用文件差异，并注明日期和限制。
- **受限**：已有明确范围的人工观察或局部证据，但不足以证明完整支持；说明依据与缺口。
- **未支持**：明确版本中有失败证据或确定的能力缺失，注明条件；不能用“没测试”代替。
- **未知/未测试**：没有足够证据；宿主宣称、配置意图或本仓库存在指令文件不算通过。

文档首稿完成不使任何环境自动升级为实测支持。行为用例通过也不证明读取隔离、审批或不外发等控制成立。

- 环境：宿主版本/安装来源、系统、实际工具执行位置、模型/服务、加载模式、框架基线和本地修改状态。

- 生命周期：新会话、入口修改、框架升级、停止与撤销分别测了什么；不得把旧版结果泛化到新版。
