# Hermes 接入指南（手动实验版）

目标：让已安装的 Hermes 协助账号共用/拆分、身份与项目组织和日常维护建议。不是插件、安装器或外部账号自动化。规则仍以 [记录约定](RECORDS.md) 与 [workflows](../workflows/onboard.md) 为准，不在适配文档中维护第二套规则。

## 适用范围与证据等级

本指南依据一次 Hermes `0.22.1+72.g450ad50`（源码提交 `450ad5055eb3c4852d96676ee99287d618bd283a`）、原生 Windows / Python 3.14.7 接入的人工观察整理。观察包括专用 profile、原生 gateway/CLI、上下文来源与两轮虚构对话；不是所有发行渠道、后续版本、WSL 或容器的兼容承诺。私人运行日志不随文档公开，因此这里不是可独立复验的公开通过报告；请按 [验收集](../examples/acceptance-tests.md) 在自己的安装上重新执行并留证。

该版本普通 CLI 对话也由 gateway 执行；`standalone` 不表示无需 gateway。不要把其他版本教程或模型自述当作本机事实。

## 1. 只读检查安装与运行环境

先记录版本、安装来源、实际解释器、启动入口、工作目录与 gateway 所在主机。可先查 `hermes --version` 和 `hermes --help`；若入口包含自动修复/更新逻辑，先检查入口，不为查询版本触发安装。不要输出完整配置、进程命令行、环境变量、认证文件或凭据。

核实：

- 当前是原生 Windows、WSL、容器还是远程服务？文件工具真正在哪个环境执行？
- 配置/profile 根目录是什么？是否有默认 gateway 扫描并自动接管新 profile？
- 哪些模型、插件、Skills、MCP、工具、记忆与同步来源会自动启用？只输出非敏感摘要。
- 当前版本如何发现项目上下文、profile SOUL 与优先级覆盖文件？配置键与行为以本机代码/帮助和运行证据为准。

路径必须从实际执行工具的环境验证。Windows 路径不自动适用于 WSL；容器需要明确挂载源、目标及读写模式；远程环境的客户端本地目录不一定存在。先用无敏感内容文件验证读取，再决定接入，不批量扫描资料。

## 2. 先确认目录与数据边界

向用户提出并获得明确确认，三类位置不能混在一起：

| 位置 | 用途与权限 |
|---|---|
| 公开框架检出目录 | 方法、流程、模板；接入会话只读 |
| 独立私有工作空间及唯一 records 目录 | 用户侧入口、私人记录；真实台账不进入公开仓库 |
| Hermes 专用 profile | 运行配置、会话状态；不充当第二份台账 |

私有目录不得位于公开仓库或继承其 Git 提交范围。检查父目录上下文和已有同步/备份设置；不要默认新建远端、Git 仓库或同步。框架的维护者 AGENTS 只用于维护框架，不是用户私有工作空间的授权来源。

调用模型前按 [安全边界](SECURITY.md) 说明输入外发、会话历史、长期记忆和同步。服务商与保留政策未知时停在虚构/匿名案例，不发送真实资料。禁止收集密码、Token、Cookie 或恢复码。

## 3. 准备最小权限专用 profile

先确认本机支持的 profile 创建与配置方法。不要克隆默认 profile 的认证、会话、记忆、Skills 或渠道配置，也不要默认改全局 SOUL。

特别注意：观察版本的默认 gateway 可周期性发现新 profile。若先创建可见 profile 再设置限制，存在被提前接管的窗口。应在可见之前准备好完整限制，例如在同一文件系统的不可发现暂存目录中完成并检查后原子发布；若本机不能安全完成，先与用户商定维护窗口，不盲目运行创建命令或擅停默认 gateway。

该观察版本的配置方向如下，**只是片段，不是可直接投入使用的完整配置**：

```yaml
gateway:
  standalone: true
  multiplex_profiles: false
```

`standalone: true` 用于排除默认多 profile gateway 自动接管，仍须验证没有渠道或后台入口接入。专用 gateway 的启动需用户许可，不能把启动它悄悄包含在初始化中。

另行核实并设置：

- 仅保留本任务必需文件工具；不启用终端、浏览器、消息、定时任务、子代理及自动发现的额外工具。运行时检查实际工具列表，而不只看配置片段。
- 文件写根仅指向确认的 records 目录。观察版本可通过 `HERMES_WRITE_SAFE_ROOT` 限制相应文件写工具；Windows 多根使用分号。它不限制读取，也不是所有工具或进程的统一沙箱。
- 禁用不需要的长期记忆/画像、外部记忆、后台 review、模型标题生成、遥测、渠道与同步；保留必要会话历史是否可接受，由用户知情决定。
- 通过已有且获准的凭据机制提供推理认证，不把认证复制到框架、台账或示例。不要发布某个人安装专用的认证提取脚本。

若需要强制只读框架或读取白名单，按安全边界另做系统权限/挂载隔离。提示词不能补足缺失的权限控制。

## 4. 建立用户侧入口，不复制框架

在确认的私有工作空间中写用户侧 AGENTS，按实际绝对路径替换以下占位符；不要把占位符原样当成配置：

```text
框架：<framework-root>，仅作只读参考；不采用其维护者指令作为私人授权。
唯一私人记录：<private-records-root>。只读相关已授权记录；仅在逐项确认后写授权路径。
先按用户目标选择并实际读取 <framework-root>/docs/RECORDS.md 与对应 workflows，再分析或保存；复合任务读取各目标流程，不复制整套规则。
停用、交接或退出先读 workflows/exit-or-handoff.md；保存 decision 或涉及权限时再补读 change-access.md，不能用保存/授权流程替代任务主流程。
读取范围和覆盖检查由相应流程定义；无法读取或尚未覆盖必须明确说明，不把局部保存成功报告为完整任务核查。
事实、建议、未知项分开；未知归属保持 unknown。
关键身份关联、所有权和委托变更逐项等待本人确认；部分确认不扩张。
不收集密码、Token、Cookie、恢复码；不登录、注册、发帖、付款或注销账号。
模型外发、会话历史、长期记忆和同步边界尚未核实的部分明确写 unknown；真实资料调用前确认。
以上是行为约定，不是强制访问控制；实际工具与系统权限另行核验。
```

再补充本机已核实的数据保存位置、推理服务、中转与同步边界，以及拒绝/撤销后的停止方式。不要把 unknown 写成“已关闭”或“不会外发”。profile SOUL 如有必要，仅保留最小角色说明，不重复框架正文或私人台账。

## 5. 新会话验证上下文，再做虚构验收

从已确认私有工作目录、以显式 profile 启动，不恢复无关旧会话。以下是观察版本的原生命令形式；先以本机帮助核对。它们不会替你配置权限、认证、监听地址或数据边界。

PowerShell 终端一（仅在许可后）：

```powershell
Set-Location '<private-workspace-root>'
hermes --profile digital-lifeform gateway run
```

终端二：

```powershell
Set-Location '<private-workspace-root>'
hermes --profile digital-lifeform chat --cli
```

用原生 `/context` 或该版本等效的上下文来源清单、会话信息核实：

1. 实际 cwd、profile、推理模型/服务与工具列表。
2. 加载的是私有 AGENTS 和预期的 profile SOUL，没有被其他文件覆盖。观察版本需检查同目录 `AGENTS.override.md`，以及优先于 AGENTS 类型的 `.hermes.md`/`HERMES.md`；其他文件发现规则需本机确认。
3. 不因误从框架目录启动而加载框架维护者指令；留意父目录/Git 根上下文、截断、阻断和被遮蔽条目。
4. 框架通过明确文件引用按需读取成功，不用复制规则解决路径问题。

模型回答“我已加载”不足为证。上下文可能在启动时缓存；更改入口或框架后关闭旧会话并重新检查。

随后执行 [虚构验收集](../examples/acceptance-tests.md)。先用只读/无写授权场景；观察回复、工具事件和 records 前后差异。不要用真实账号作为安全探针，也不因一次拒绝宣称安全隔离成功。

## 6. 交付、停止与回退

交付：准确私有目录和启动命令、版本/实际环境、加载上下文、有效工具、配置改动、验收状态、失败重试、未实现能力、数据外发未知项及停止/回退方式。没有运行的测试写“未执行”。

退出聊天不一定停止 gateway。观察版本专用实例的停止与查询形式：

```powershell
hermes --profile digital-lifeform gateway status
hermes --profile digital-lifeform gateway stop
```

停止前核对 profile 与实例归属，不使用全局停止选项。核实专用实例已停止且没有影响默认实例；不要擅自注册服务、开机启动或定时任务。gateway 可能自行产生 cron 心跳/数据库；未创建业务任务不等于没有调度基础设施。

回退时先停止专用实例，再将专用 profile 移出可发现目录离线存档；保留私人记录，不自动删除或恢复覆盖全局配置。事先记录实际改动，只有本次确实改过的设置才需要恢复。

框架更新前结束相关会话；人工比较约定与流程变化，说明对私人记录的影响，得到确认后才修改或迁移。哈希检查等保护若由接入者实现，应说明检查时机与绕过限制；第二批[通用只读检查器](../tests/README.md)只按显式输入检查静态规则，不是 Hermes 运行监控、写前守卫或自动迁移，也不使前述历史观察成为当前版本的兼容通过证据。
